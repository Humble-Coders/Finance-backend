# [M3] Turn redacted statement text into transaction rows

## 📖 Story / Why

M3 is the load-bearing milestone: every later feature — the budget generator, the health
score, the dashboard, the chatbot — is only as good as the transaction data this produces.

On 2026-09-21 the pipeline moved onto the device (PRD §9). The apps pull the text out of a
statement locally, redact it locally, and send **text only** — the document itself never
reaches us. This ticket is the server half: an endpoint that takes that redacted text and
returns structured transaction rows.

The model does the row reconstruction because neither a PDF text layer nor OCR carries table
semantics. That is a deliberate choice with a payoff worth stating: a misparse is fixed by a
prompt change we deploy, not an app release users have to install.

- **An LLM API key**, set as `LLM_API_KEY` in the Render `finai-api` environment — from the
  manager via secure channel. **For this ticket a free-tier key is fine** (Google AI Studio's
  Gemini free tier is the suggested one: generous limits and reliable structured JSON output);
  the paid Anthropic key replaces it later without a code change.
- **Hard rule that comes with that:** a free tier's terms generally permit the provider to use
  your inputs to improve their models, which PRD Appendix A.3 forbids for this data. So the
  free key may only ever see **synthetic fixtures**. Before a single real user's statement is
  parsed, the key swaps to a paid, no-training API tier. Read the provider's actual terms
  before pointing anything real at it — do not take this ticket's word for it.
- Docker for local database tests (optional — CI runs them).
- **No document-AI vendor account is needed.** If you find yourself signing up for Textract or
  Google Document AI, you are building the superseded design.

## ✅ Scope / What to build

- [ ] **Migration — make the import record match reality.** The table describes an uploaded
      file we no longer receive. Rename `document_upload` → `statement_import`; drop
      `storage_path`, `content_type`, `byte_size`, `deleted_at`; add `source_kind`
      (`pdf_text` | `ocr`) and `page_count`. Keep `confirmed_at` (the review step still
      confirms rows), `extracted_count`, `status`, `failure_reason`. Update the RLS policy list
      (`7ce291039fe7`) and `transaction.document_upload_id` → `statement_import_id`.
      **No filename column:** a filename like `statement-jane-smith.pdf` is personal data we
      have no use for.
- [ ] **`POST /statements/parse`** — takes redacted text, returns rows. Request:
      `{source_kind, page_count, text, account_id?}`; response:
      `{import_id, rows: [{occurred_on, description, amount, direction, confidence}], model,
      unparsed_line_count}`. Amounts are **decimal strings** throughout (PRD §4.4).
      `account_id` is optional here and validated for household ownership when present — 3.3
      makes it required, once there is a way to create an account.
- [ ] **LLM client behind one module** (`app/services/llm.py`): a protocol, one real adapter,
      and a fake for tests. **Provider, model and base URL come from settings**
      (`LLM_PROVIDER`, `LLM_MODEL`), because this ticket deliberately ships on a free tier and
      must move to a paid one by configuration, not by editing the endpoint. Prompt text lives
      in a versioned constant, and the model name goes in the response so a bad parse can be
      traced to what produced it.
- [ ] **Chunking.** Split long text into overlapping windows server-side, merge the rows, and
      drop duplicates created by the overlap on `(occurred_on, amount, description)`. One
      statement is one request; the client does not chunk.
- [ ] **Anti-hallucination guard (non-negotiable).** Every returned amount must appear
      **verbatim in the submitted text**. A row whose amount does not is dropped and counted in
      `unparsed_line_count`, never returned as a transaction. A finance product may not invent
      a figure, and a model asked to read a table will occasionally produce one.
- [ ] **Validation.** Reject text over 1 MB (413) and responses over 2,000 rows. Dates must
      parse to a real date; amounts must be valid for the household's currency via
      `app/core/money.py`; unknown direction defaults to `debit` **only** when the text shows a
      sign or a debit column, otherwise the row is flagged low-confidence.
- [ ] **Express consent before the first import** (PRD Appendix A.5 #1). Add
      `PolicyKind.ai_processing`, seed a version, and refuse with **409 `consent_required`**
      naming the version until a `ConsentEvent` exists for it. This is a separate consent from
      the account terms and must not be bundled with them.
- [ ] **Monthly quota.** Free tier is 1 import per calendar month (PRD F2), counted from
      `statement_import` rows. Over it: **429 `import_quota_exceeded`**, saying when it resets.
      The limit is one settings-backed constant per plan; 7.1 moves it into entitlements.
- [ ] **Failure handling.** Model timeout or error → the import row is marked `failed` with a
      reason, and the endpoint returns **502 `parse_failed`**. The user still holds the file,
      so a retry is a retry — not a half-imported statement.
- [ ] **Privacy.** Never log the submitted text, a row, a description or an amount — counts,
      durations, model name and codes only. **A 422 must not echo the statement text**, which
      is Pydantic's default behaviour and would put it straight into the response and the logs.
- [ ] Remove the dead `document_ai_credentials` setting and `extraction_queue_name` if nothing
      else references it.
- [ ] Tests (see Acceptance Criteria).

## 🎯 Acceptance Criteria

- [ ] Posting redacted text from a realistic Canadian statement fixture returns rows whose
      dates, amounts and descriptions match the fixture exactly; amounts round-trip as decimal
      strings and no `float` appears anywhere in the path.
- [ ] A fake model that returns an amount **not present** in the submitted text has that row
      dropped and counted, not returned — proven by a test.
- [ ] Text long enough to chunk produces each transaction **once**, with no duplicate from the
      window overlap — proven by a test with a transaction deliberately placed on the seam.
- [ ] Before consent exists, the endpoint returns 409 `consent_required`; after a
      `ConsentEvent` for the seeded `ai_processing` version, it succeeds. The consent is
      recorded with its policy version.
- [ ] A free household's second import in a calendar month returns 429 `import_quota_exceeded`;
      the first still succeeded.
- [ ] With the `document_upload` feature disabled for the household, the endpoint returns
      403 `feature_unavailable` before any model call is made (no spend on a refused request).
- [ ] A model timeout returns 502 `parse_failed`, the `statement_import` row reads `failed`
      with a reason, and no transaction rows are returned.
- [ ] **No statement content anywhere in logs** — a test asserts the submitted text, a
      description and an amount never appear in captured log output, and that a 422 response
      body does not echo the text.
- [ ] One household can never read another's `statement_import` rows (covered by a test).
- [ ] Changing `LLM_PROVIDER` / `LLM_MODEL` selects a different adapter with no change to the
      endpoint or the prompt — proven by a test with two fakes registered.
- [ ] Every test runs against **synthetic fixtures**; no real bank statement, of anyone's, is
      committed to this repo or sent to a free-tier provider.
- [ ] Migrations apply, reverse and re-apply cleanly in CI's `database` job; `ruff check`,
      `ruff format --check` and `pytest` pass; CI green.
